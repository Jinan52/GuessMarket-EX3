A. System overview
This submission is a Client–Server implementation of Guess Market EX3.

- Server: one Tomcat web application, deployed as guess-market.war, context path /guess-market.
- Client: a JavaFX desktop UI. It talks to the server only over HTTP. The server URL is fixed in the client:
  http://localhost:8080/guess-market
  The client does not ask the user for a server URL.
- Shared engine: MarketSystem runs in-process inside Tomcat (ServletContext attribute). The JavaFX client does not instantiate MarketSystem and does not parse EX3 XML locally. The client depends on the engine module only for shared DTO/model types used to deserialize JSON.
- JSON: Gson is used on both sides.
- XML: EX3 XML is uploaded from the client machine and parsed on the server with JAXB.

B. How to run
Requirements:
- 64-bit JDK 25 on Windows
- Apache Tomcat 10 (Jakarta Servlet)
- JAVA_HOME pointing at JDK 25 is recommended

1. Copy guess-market.war into Tomcat's webapps folder.
2. Start Tomcat. Wait until the application is available at:
   http://localhost:8080/guess-market
3. Open the client folder and run run.bat (double-click, or from Command Prompt).
   IntelliJ is not required.
4. On the login screen, enter a unique user name. There is no password.
5. To upload events, use the client file chooser and select an EX3 XML file.
   Sample files are included under client\samples.

To start a second trader, run run.bat again (a second JavaFX window).

C. Main EX3 behavior
- Unique-name login, no password. A duplicate name is rejected and can be retried.
- XML is uploaded from the client machine through HTTP multipart POST /upload.
- Upload appends events. It does not replace the whole system.
- The uploading user becomes Market Maker of the uploaded events.
- LMSR events: prices, purchase, close, winner, payouts.
- Order Book events: pending orders, statistics, participants, submit BUY/SELL, close.
- Users start with cash 0.0 and add funds from the client.
- Private account history, holdings, and participated active/closed events are shown for the logged-in user.
- Other Users is a public directory: name, balance, MM YES/NO. Clicking another user does not change identity.
- Automatic Pull refresh every 1 second (assignment maximum is 2 seconds).
- No persistence: restarting Tomcat resets all in-memory users, events, accounts, and chat.

D. Important implementation choices
- Initial new-user balance = 0.0
- Internal numeric event IDs are generated by the server to preserve existing engine APIs. XML does not supply those IDs.
- The client always uses the logged-in name (ClientSession) for user-specific requests.
- No HttpSession was added. Identity is the userName sent on each request.
- Order Book UI uses summary / event-account / pending-orders / order-book-statistics / order-book-participants rather than a unified EventDetails payload. EventDetails is used for LMSR.
- Upload is streamed to the server and is not intentionally saved as an application file.
- Polling interval = 1 second. One JavaFX Timeline per main window. GET only. No automatic POST.

G. Bonus
Bonus implemented: Yes — Global Chat (5 points)

- One global shared chat room for all connected / logged-in users.
- Everyone sees every message. There are no private messages, event chats, or rooms.
- Each line stores sender (userName), message text, and a server-side timestamp.
- Chat is in-memory on the server only (ServletContext). It is not written to disk.
- GET /chat is pulled through the existing 1-second polling cycle. Polling never sends chat.
- POST /chat-send runs only when the user presses Send (or Enter in the chat field).
- Restarting Tomcat / the server clears chat, along with all other in-memory data.
